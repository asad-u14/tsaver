tsaver — usage reference

A local, on-disk token/output saver for AI coding agents. No telemetry, no cloud, no network calls — everything lives under ~/.tsaver/ and project-local .tsaver/.

Why tsaver exists

AI coding agents like Claude Code spend a large share of their context window — and your token budget — reading raw command output that has nothing to do with the task at hand. A single npm install or pytest run can dump hundreds of lines of progress bars, repeated log lines, and install chatter into the conversation, and every one of those lines is tokens the model has to read before it can get to the one line that actually matters: the error, the failure, the summary.

The same problem shows up in other forms: an MCP tool can return a JSON blob with megabytes of nested data when only a handful of fields are relevant; a PDF or Jupyter notebook an agent needs to read might be mostly formatting and binary overhead; a repo-wide grep for "where is this function used" burns several tool calls that a small local index could answer in one.

tsaver sits between the agent and all of that noise. It wraps the commands an agent runs, compacts the data it reads, and keeps everything that got filtered out recoverable on disk — so you get the token savings without ever losing information for good. It runs entirely locally: no data leaves your machine, there's no telemetry, and nothing needs a network connection to work.

Who this is for: anyone running Claude Code (or another agent) against a real codebase, where routine commands — installs, test suites, builds, API calls — are quietly eating context on noise instead of signal. If you've ever watched an agent's context fill up with PASSED lines or spinner frames, that's the problem tsaver is built to fix.

Install

git clone git@gitlab.com:ai-projects-14/tsaver.git
cd tsaver
npm install
npm run build
npm link

npm link makes the tsaver command available globally.

Do not use npm install -g git+ssh://git@gitlab.com/.... npm's git installer fetches GitLab packages via the repository/archive.tar.gz REST API rather than a real git clone, and that endpoint can 404 on some networks (observed on a corporate network with TLS interception). Clone + npm link avoids this entirely.

To update later:

cd /path/to/your/tsaver/clone
git pull
npm install
npm run build

tsaver run

tsaver run [--stats] -- <command> [args...]

Spawns <command>, captures stdout/stderr, and streams each line through a filter before printing it — stripping noise while guaranteeing failures survive. Exit code is propagated unchanged.

Filter selection order

  1. A custom .toml filter matching the command name.
  2. A built-in profile, if one exists: pytest / py.test, npm.
  3. Otherwise, the generic filter (fallback).

Generic filter behavior

  • Always keeps the first 5 lines and the last 20 lines of output.
  • Collapses 3 or more consecutive near-duplicate lines (digits normalized before comparing) into one line with a (×N) suffix.
  • Drops progress-bar/spinner lines (carriage returns, [===> ] 42%, bare NN% |).
  • Always keeps lines matching /\b(error|fail(?:ed|ure)?|exception|traceback)\b/i.
  • On non-zero exit, appends any last-20-window lines not already emitted under a --- last lines before exit --- marker.

pytest profile

Keeps FAILED, ERROR, E (assertion detail), and the summary line. Collapses passing-dot/PASSED lines into a single N passed note.

npm profile

Keeps npm error/npm ERR!/npm warn/install-summary lines and anything matching error|fail. Drops npm notice/npm timing/spinner lines.

--stats

tsaver stats
  lines                   32 -> 8  (75.0% reduction)
  bytes                   367 -> 90  (75.5% reduction)
  words (approx. tokens)  63 -> 16  (74.6% reduction)

Printed to stderr so it doesn't pollute piped stdout. "Words" is a whitespace-split count used as an approximate token proxy, not an actual tokenizer count.

History

Writes a kind: "run" entry with full raw/filtered text, exit code, which filter handled it, and source: "hook" if invoked via the Claude Code hook (otherwise "manual").

tsaver run --stats -- npm install
tsaver run --stats -- pytest
tsaver run -- cargo build

tsaver read

tsaver read [--stats] [--cache] <path>

Optimizes a file for an agent to consume, dispatching by extension:

ExtensionBehavior
.pdfExtracts plain text via pdf-parse.
.ipynbConverts to Markdown: markdown cells as-is, code cells as fenced blocks, cell outputs over 20 lines truncated with a marker.
.png .jpg .jpeg .gif .webpResizes (if >1024px on the longest side) via jimp, writes <name>.optimized.<ext> alongside the original.
anything elsePassthrough — prints as-is, 0% reduction, still logged.

--cache: writes the optimized content to ~/.tsaver/cache/<hash>.md (or points at the .optimized.<ext> image file) and prints only that path — used internally by the Claude Code Read hook, not generally needed interactively.

tsaver read --stats report.pdf
tsaver read notebook.ipynb
tsaver read screenshot.png

History entry: kind: "read", rawPath set to the original file (so retrieve re-reads it instead of duplicating its bytes).

tsaver mcp

tsaver mcp [--stats] [--max-string N] [--max-array N] [file]

Compacts a JSON document — e.g. a captured MCP tool response — while guaranteeing the output stays valid JSON. Reads from file if given, otherwise stdin.

  • Strings longer than --max-string (default 500) truncated with an inline "...(N more chars)" suffix.
  • Arrays longer than --max-array (default 20) keep the first 3 and last 3 items, splicing in a "...(N more items)" marker.
  • Objects/nested values processed recursively.
  • Invalid JSON input exits 1 with a parse error — nothing is written.
curl -s https://api.example.com/big-response.json | tsaver mcp --stats
tsaver mcp --stats --max-string 200 --max-array 10 response.json

tsaver filters gaps

tsaver filters gaps [--top N]

Scans history for run entries that fell back to the generic filter, groups by command basename, ranks by total raw bytes. Default --top is 10.

Commands without a custom filter (generic fallback)
  node                 runs=4  raw_bytes=388  avg_reduction=71.4%

Add .tsaver/filters/<command>.toml to improve filtering for these.

tsaver report

tsaver report

Aggregate summary: total entries, per-kind byte counts and reduction %, an approx. tokens saved line, and a "Recent entries" list. "Tokens saved" is a whitespace-split word-count proxy (rawWords - filteredWords) — an approximation, not an exact tokenizer count. Entries with source: "hook" are counted in the aggregate stats but omitted from "Recent entries" so that list stays focused on commands you ran yourself.

tsaver retrieve

tsaver retrieve <id>

Recovers the original, unfiltered content for any past history entry by id. For run/mcp entries, prints the stored rawText. For read entries, re-reads the original file from its stored rawPath.

tsaver retrieve a1b2c3d4e5

tsaver history clear

tsaver history clear [--force]

Permanently deletes every history entry under ~/.tsaver/history/. Nothing else is touched — the cache under ~/.tsaver/cache/ and any installed hooks/custom filters are left alone.

  • Without --force, refuses and prints how many entries would be deleted.
  • With --force, deletes everything and prints a count of entries removed.
  • If history is already empty, prints a short confirmation and exits 0 either way.
  • After clearing, tsaver report and tsaver dashboard both reset to their "no history yet" state.
tsaver history clear
tsaver history clear --force

tsaver init --claude

tsaver init --claude

Installs two Claude Code PreToolUse hooks:

  1. On the Bash tool — every Bash command Claude Code runs (terminal or VS Code extension) is automatically rerouted through tsaver run.
  2. On the Read tool — every Read of a .pdf, .ipynb, or image file is automatically redirected through tsaver read first, so Claude sees the optimized/extracted content instead of the raw original.

No manual prefixing or tsaver read calls needed for either case.

What it does

  • Writes ~/.claude/hooks/tsaver-reroute.cjs (Bash hook) and ~/.claude/hooks/tsaver-read-reroute.cjs (Read hook), both mode 0o755.
  • Merges two hooks.PreToolUse entries into ~/.claude/settings.json — never overwrites existing settings.
  • Re-running always refreshes both hook scripts' content, even if the settings.json entries already exist.

Why the hooks embed an absolute path

Both hooks invoke node '<resolved absolute path>' ... rather than a bare tsaver command. This fixes a real bug: Claude Code's hook commands can run in a non-interactive shell that never sources the init files a tool like nvm relies on for PATH. Relying on PATH caused every Bash call to silently fail, freezing the session. The absolute-path fix makes both hooks immune to PATH/shell-context issues.

What the Bash hook does NOT reroute

Commands matching this pattern run directly, unmodified — wrapping them would silently break their effect on the rest of the session:

cd, pushd, popd, export, source, . (dot), alias, unset, declare, local, readonly, set, exec

How the Read hook works

On every Read call, checks the extension against .pdf .ipynb .png .jpg .jpeg .gif .webp (case-insensitive). If it matches and isn't already a cache/optimized path, it runs tsaver read --cache <path> and redirects to the single-line path it prints back:

  • PDFs/notebooks → a cached extracted-text/Markdown file under ~/.tsaver/cache/.
  • Images → the actual resized <name>.optimized.<ext> image file, never text — Claude's Read tool needs real image bytes for vision.

If tsaver read fails for any reason (corrupt file, timeout after 30s), the hook falls through silently and Claude reads the original file unmodified — it never blocks the Read.

Manual step required: after running tsaver init --claude, Claude Code must reload hooks — open /hooks once or restart Claude Code. This isn't automatic.

tsaver graph

tsaver graph build [--dir <path>] tsaver graph query <symbol> [--dir <path>]
Heuristic, not an AST. This is a regex-based pattern index — it does not understand scope, types, or shadowing. Expect occasional false positives (a common identifier matching unrelated text) and false negatives (unusual syntax). Treat its output as a fast pointer, not ground truth.

Supported languages

  • JS/TS (.ts .tsx .js .jsx .mjs .cjs): function NAME, class NAME, const/let NAME = (...) =>, const/let NAME = function, import statements, require(...).
  • Python (.py): def NAME, class NAME, import X, from X import Y.
  • Any other extension is skipped entirely — no generic fallback.

build

Walks the target directory (default: cwd), skipping node_modules, .git, dist, build, out, .tsaver, coverage, and hidden directories. Writes to <dir>/.tsaver/graph.json. Re-run after significant changes — it does not auto-refresh.

query

Exact case-sensitive match first; falls back to case-insensitive substring match if nothing matches exactly. Output grouped into Definitions, Imported by, and References (capped at 50 shown).

tsaver graph build
tsaver graph query selectFilter
tsaver graph build --dir ~/other-project

tsaver dashboard

tsaver dashboard [--port 4173]

Starts a local-only web dashboard over the same history data tsaver report uses.

  • Binds to 127.0.0.1 only — nothing exposed on the network, no data leaves the machine.
  • Built on Node's built-in http module — no new dependencies, no bundler.
  • Routes: GET /, GET /api/summary, GET /api/history?limit=N.
  • Top-of-page stat tiles: total entries, approx. tokens saved (highlighted), raw bytes, filtered bytes, overall reduction %.
  • The history table includes a Tokens saved column per row. "Tokens saved" is the same whitespace-split word-count proxy used by --stats — an approximation, not an exact tokenizer count.
  • Auto-refreshes every 5 seconds.
  • Opens your default browser automatically (best-effort; the printed URL always works manually).
  • Stop with Ctrl+C. If the port is in use, suggests --port <other>.
tsaver dashboard
tsaver dashboard --port 5000

Custom filters

Define keep/drop rules for a specific command via TOML:

# .tsaver/filters/mytool.toml
command = "mytool"
keep = ["^ERROR", "^FAIL"]
drop = ["^progress"]
  • Project-local (.tsaver/filters/*.toml) override global (~/.tsaver/filters/*.toml) filters for the same command.
  • Each pattern is a JS regex source string, no delimiters ("^ERROR" not /^ERROR/).
  • Per-line order: drop wins first → keep wins second (flushing any pending repeat-collapse buffer) → otherwise goes through the same repeat-collapsing logic as the generic filter.
  • If the command exits non-zero and no keep pattern ever matched, a marker line notes the exit code.

How tsaver actually works

This section ties together everything above into one end-to-end picture: what's stored where, how each command parses its input, and what the numbers you see actually mean.

Everything tsaver stores, and where

All of it lives under your home directory — nothing is sent anywhere, nothing requires a server:

PathWritten byContents
~/.tsaver/history/<id>.jsonrun, read, mcp (one file per invocation)Full record of what happened — see the entry shape below.
~/.tsaver/cache/<sha1-of-path>.mdtsaver read --cache (the Claude Code Read hook)Extracted text/Markdown for a PDF or notebook, keyed by a SHA-1 hash of the original file's absolute path. Overwritten fresh on every Read — no staleness tracking, since the hook regenerates it live each call.
<original-file>.optimized.<ext> (next to the original, not under ~/.tsaver/)tsaver read on an imageThe resized image itself. Images never go through the text cache — the Read hook needs real image bytes for Claude's vision, so the redirect always points at this file.
.tsaver/filters/*.toml (project) and ~/.tsaver/filters/*.toml (global)You, by handCustom per-command filter rules. Project-local overrides global for the same command.
.tsaver/graph.jsontsaver graph buildThe regex-based symbol index for that directory.
~/.claude/hooks/tsaver-reroute.cjs and tsaver-read-reroute.cjstsaver init --claudeThe two generated hook scripts.

Nothing here is ever deleted automatically. History accumulates indefinitely until you run tsaver history clear; the cache directory and .optimized.<ext> files are likewise left in place until removed by hand.

History entry shape

Every run, read, and mcp invocation writes one JSON file to ~/.tsaver/history/<id>.json (a 10-character hex id):

{
  id: string;
  timestamp: string;            // ISO 8601
  kind: "run" | "read" | "mcp";
  label: string;                 // truncated to one line + "...(+N more lines)" if long
  exitCode?: number | null;      // run only — the wrapped command's exit code
  filterName?: string;           // run only — "generic" | "pytest" | "npm" | "custom:<name>"
  source?: "hook" | "manual";    // run and read — hook-triggered vs. you ran it yourself
  stats: { rawLines, filteredLines, rawBytes, filteredBytes, rawWords, filteredWords: number };
  rawText?: string;    // run/mcp — full original content, recoverable via retrieve
  rawPath?: string;    // read — original file's path, re-read by retrieve rather than duplicated here
  filteredText: string;
}

How each command actually parses/processes its input

  • run: spawns the command with child_process.spawn, reads stdout/stderr line by line via Node's readline (so large output never sits fully in memory before filtering). Each line goes to the active filter's processLine, which keeps, drops, or buffers it for possible repeat-collapsing.
  • read: dispatches purely by file extension, not content sniffing — .pdf uses pdf-parse to extract embedded text objects from the PDF structure; .ipynb is parsed as JSON (it's just a JSON document) and walked cell-by-cell; images are decoded and resized by jimp; anything else is read as plain UTF-8 text unchanged.
  • mcp: parses the input with JSON.parse up front — a failure here reports the error and exits without writing anything. The compaction walk recurses through the parsed value truncating long strings/arrays, then re-serializes with JSON.stringify, which is what guarantees valid JSON output.
  • graph build: walks the directory tree (skipping node_modules, .git, dist, build, out, .tsaver, coverage, hidden dirs), reads each matching file as UTF-8 text, and runs it line-by-line through a fixed set of regexes per language — it never builds an actual syntax tree.

What the byte and "tokens saved" numbers actually mean — and a real caveat

Every entry tracks two independent before/after measurements: bytes, and "words" (a whitespace-split word count used as an approximate token proxy, not an exact tokenizer count — labeled as such everywhere it's shown).

For run and mcp, raw and filtered are both genuinely comparable plain text, so both numbers are real and meaningful. A representative real test, run live through tsaver run on a script producing 50 repetitive pass lines plus one real error: 52 → 8 lines, 1,425 → 247 bytes (82.7% reduction), 163 → 32 words (80.4% reduction, ~131 tokens saved) — the repeated lines collapsed to one (×45) line while the error and summary stayed intact.

For PDF and notebook reads, the word-count metric is not meaningful and will usually show 0 "tokens saved" even though real savings are large. There's no plain-text "raw" version of a binary PDF to count words in before extraction happens, so tsaver read sets the raw word count equal to the already-extracted text's word count — they're always identical for these file kinds. The byte reduction is still real (a 2 MB PDF reduced to a few KB of text is a genuine ~2 MB reduction), so for PDF/notebook entries, check the byte numbers rather than reading "0 tokens saved" as "this did nothing."

Troubleshooting

npm install -g git+ssh://... fails (404, SELF_SIGNED_CERT, extraction errors)

npm fetches GitLab packages via repository/archive.tar.gz rather than a real clone, and that endpoint can 404 on networks with TLS-intercepting proxies. Use clone + npm link instead.

tsaver: command not found, or it suddenly stops working

  • Dangling global symlink from a partial git-install attempt — npm uninstall -g tsaver, remove any leftover symlink, reinstall via clone + link.
  • Lost executable bit on dist/cli.js — chmod +x dist/cli.js, or re-run npm run build.
  • Local changes blocking git pull — git checkout -- dist/cli.js package-lock.json (both are regenerated), then pull again.

git pull/fetch times out over SSH

Some networks block outbound port 22. Fetch over HTTPS for one-off access: git pull https://gitlab.com/ai-projects-14/tsaver.git main

The Claude Code hook doesn't seem to be filtering anything

Claude Code only reloads hook config at session start or when you open /hooks — editing ~/.claude/settings.json has no effect on an already-running session until one of those happens.

tsaver — local-first, no telemetry, no network calls.
